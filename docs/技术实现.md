## 分层结构

脚本自上而下分为 10 段，用注释横线显式分隔，**下层不依赖上层**：

```
┌──────────────────────────────────────────────────────┐
│ ⓪ 多语言            VERSION / LANG / STR / t()         │
├──────────────────────────────────────────────────────┤
│ ① 常量与配置项      SCRIPT_DIR / DEFAULT_OUT / 阈值    │
├──────────────────────────────────────────────────────┤
│ ② 工具函数          has_text trim basename dirname …  │
├──────────────────────────────────────────────────────┤
│ ③ 文件后端          try_write 系列（纯 I/O，无业务）    │
├──────────────────────────────────────────────────────┤
│ ④ 路径与数值        norm_path resolve_out_path parse_num│
├──────────────────────────────────────────────────────┤
│ ⑤ 采集              load_ranges load_selected all_static│
├──────────────────────────────────────────────────────┤
│ ⑥ 业务              make_record verify_rows sort_rows  │
├──────────────────────────────────────────────────────┤
│ ⑦ 格式化            fmt_lua fmt_json fmt_csv render    │
├──────────────────────────────────────────────────────┤
│ ⑧ 配置              serialize deserialize read/write   │
├──────────────────────────────────────────────────────┤
│ ⑨ 界面              step_* flow_* main_menu            │
└──────────────────────────────────────────────────────┘
```

设计约束（原文注释里明确写出）：

- **界面层只弹窗，不算数据**；业务层只算数据，不弹窗。
- **所有面向用户的文案必须走 `t(key)`**，不允许再写死字符串；新增文案时两张词表都要加。
- 唯一的例外是两处 `gg.toast`（配置损坏、配置保存失败）与 `verify_rows` 之后的确认框 —— 前者属于配置层的失败反馈，后者是流程决策，都不参与数据换算。
- 所有对外部 API（`io.*`、`os.*`、`gg.*`）的调用都套 `pcall`，因为 GG 在不同 ROM 上的实现差异会导致「正常应该成功」的调用直接抛错。

## 路径层

### `norm_path` 的处理顺序

顺序不可随意调换 —— 每步都可能产生下一步依赖的形态：

| # | 操作 | 目的 |
| --- | --- | --- |
| 1 | `trim` | 去掉首尾空白（用户粘贴常带空格） |
| 2 | 剥 `content://<authority>` / `file://` / `document://` / 任意 `scheme://` | SAF 与文件选择器返回的 URI 前缀 |
| 3 | 选择性还原 `%XX` | 只还原会改变语义的 4 个字符 |
| 4 | 拆 `/tree/<tree>/document/<doc>` | SAF 目录树 + 文档 ID 的复合形态 |
| 5 | 剥残留的 `tree/` `document/` | 单段形态 |
| 6 | `primary:` → `/storage/emulated/0/` | SAF 的存储卷别名 |
| 7 | `\` → `/` | Windows 风格分隔符 |
| 8 | 首字符必须是 `/`，否则返回空串 | 相对路径一律判废 |

典型输入输出：

| 输入 | 输出 |
| --- | --- |
| `/sdcard/base.lua` | `/sdcard/base.lua` |
| `file:///sdcard/base.lua` | `/sdcard/base.lua` |
| `content://com.android.externalstorage.documents/tree/primary%3ADownload/document/primary%3ADownload%2Fbase.lua` | `/storage/emulated/0/Download/base.lua` |
| `content://com.android.externalstorage.documents/document/primary%3Abase.lua` | `/storage/emulated/0/base.lua` |
| `primary:Download/base.lua` | `/storage/emulated/0/Download/base.lua` |
| `./base.lua` | `""`（判废） |
| `已输出的基址.lua` | `""`（判废，交由调用方回退） |

### 为什么只还原 4 个字符

```lua
s = s:gsub("%%(%x%x)", function(h)
  local c = tonumber(h, 16)
  if c == 0x25 then return "%" end
  if c == 0x2F then return "/" end
  if c == 0x3A then return ":" end
  if c == 0x20 then return " " end
  return "%" .. h
end)
```

全量解码会把 UTF-8 中文文件名的字节序列当成分散的 `%XX` 逐个还原，得到非法字节串；而 `%2C`（逗号）、`%28`（括号）这类转义对路径语义没有影响，保持原样更安全。

### `resolve_out_path` 的兜底

```
norm_path(p)
  ├─ 空 → 用原串
  ├─ 仍为空 或 以 "/" 结尾（目录而非文件）→ 返回 nil
  ├─ path_ok（长度 < 240 且以 "/" 开头）→ 原样返回
  └─ 否则 → SCRIPT_DIR + basename
```

这里**不做写前探测**（不试写、不 `access`），可写性完全交给 `try_write` 在实际写入时判定 —— 否则每次检查都会在目录里留下探测文件。

`path_ok` 的 240 字符上限来自常见文件系统的 `NAME_MAX`(255) 与路径长度限制的折中，中文路径按字节算会更快触顶，属于保守设定。

## 文件后端

### `try_write` 决策树

```
try_write(path, blob)
│
├─ blob 非字符串 / path 不合法 / 文件名为空 → 直接失败
│
├─ tmp = dir + "." + name + ".lt" + <时间>_<序号>_<随机> + ".tmp"
├─ raw_write(tmp, blob)
│   │
│   ├─ 成功
│   │   ├─ ① rename(tmp → path)          ✅ 返回 path
│   │   ├─ ② remove(path) + rename 重试   ✅ 返回 path
│   │   ├─ ③ remove(path) + 直写 path     ✅ 返回 path（顺手清理 tmp）
│   │   ├─ ④ rename 到 alt（原名_时间戳.ext）✅ 返回 alt
│   │   ├─ ⑤ 直写 alt                     ✅ 返回 alt
│   │   ├─ ⑥ tmp 可读探测通过             ✅ 返回 tmp
│   │   └─ ⑦ 清理 tmp，返回 "stale FUSE cache"
│   │
│   └─ 失败
│       ├─ remove(path) + 直写 path        ✅ 返回 path
│       ├─ path 可读探测通过               ✅ 返回 path
│       └─ 清理 tmp，返回具体错误
```

关键点：

- **临时文件名唯一**：`时间 + 自增序号 + 随机数`（`uniq_suffix`），三次来源都用 `pcall` 包裹，任一不可用也不影响拼装，保证同一秒内多次写入不撞名。
- **临时文件带 `.tmp` 后缀且以 `.` 开头**：便于人工识别与清理；`drop_tmp` 删不掉时会改名为 `.bak`，避免脏文件堆积成 `.tmp`。
- **主判据是写入/关闭的返回值**，`probe_readable` 只作旁证。分区存储下「写成功但立刻读不到」是常态，若拿读回当唯一判据会误报失败。
- **`saved_path` 可能与传入路径不同**：所有调用方都必须使用返回值而不是原始参数 —— `write_output`、`write_cfg` 都遵循这一点，回执里也会标注「已改存」。

### `raw_write` 的模式轮询

```lua
local modes = { "wb", "w", "w+b", "w+" }
```

GG 的 `io` 在不同 ROM 模式下对模式字符串的接受度不一致（有的只认 `wb`，有的对 `w+b` 支持更好）。逐个尝试并在每次尝试后 `flush` + `close`，任何一个成功即返回。

`f:write()` 也被 `pcall` 包裹并检查返回值 —— 部分实现会在磁盘满时静默返回 `nil` 而不抛错。

### 删除与探测

```lua
local function safe_remove(path)
  local ok, res = pcall(os.remove, path)
  return ok and is_true(res)
end
```

`os.remove` 在部分 ROM 上对不存在的文件会抛错而不是返回 `nil, err`，所以必须 `pcall`；`is_true` 把「返回 `nil`」和「返回 `false`」统一视为失败。

`probe_readable` 最多重试 `VERIFY_TRIES = 3` 次，间隔 `RETRY_SLEEP = 120ms` —— 分区存储下新建文件的可见性延迟通常在百毫秒级。

## 数值层

### `parse_num` 的解析流程

```
trim → 去千位逗号
  ├─ 含 "~" → 取 "~" 之后的子串（区间取上限）
  ├─ 首字符 "-" → 记负数标记，剥掉 "-"
  ├─ 前缀 "0x"/"0X"
  │   ├─ tonumber(hex, 16)
  │   └─ 若得到负数且原串是纯 hex → 手工按位累加为浮点
  └─ 否则 tonumber(s)
  └─ 过滤 nil / nan / ±inf
  └─ 按负数标记取反
```

两个细节值得注意：

**1. 大 hex 的手工累加**

Lua 5.3 的 `tonumber("FFFFFFFFFFFFFFFF", 16)` 会按 64 位整数回绕成负数。此时脚本改用浮点逐位累加：

```lua
local acc = 0.0
for i = 1, #hex do acc = acc * 16.0 + tonumber(hex:sub(i, i), 16) end
```

这样至少能得到量级正确的正数（受双精度 53 位有效位限制，超大值仍会丢精度 —— 见 README 的已知限制）。

**2. `~` 在负号之前处理**

顺序是「先取区间上限，再判负号」，所以 `-1~5` 会得到 `5` 而不是 `-5`。这是刻意的：GG 的搜索结果区间写法（如 `100~200`）是主要使用场景，负数区间极少出现。

### 字面量输出

```lua
local function num_to_literal(n)
  local s = tostring(n)
  if s:find(".", 1, true) or s:find("e", 1, true)
     or s:find("inf", 1, true) or s:find("nan", 1, true) then
    return s
  end
  return string.format("%d", n)
end
```

`tostring(12345.0)` 在 Lua 5.3 下是 `"12345.0"`，直接拼进生成的脚本虽然合法但难看，且部分场景下 `Dword` 写入浮点字面量会引发类型歧义。这里统一成 `12345`。

### 地址格式化

```lua
local function hex_addr(v)
  if type(v) ~= "number" then return "?" end
  if v ~= v or v == math.huge or v == -math.huge then return "?" end
  return string.format("0x%X", math.floor(v))
end
```

`%X` 遇到非整数值会**抛错**（`number has no integer representation`），所以必须先 `math.floor`；`nan` 的 `v ~= v` 判断放在最前，避免 `math.floor(nan)` 的行为差异。

## 采集层

### 段表构建

```lua
for _, r in ipairs(list) do
  if r.state and STATIC_STATES[r.state] then
    static_list[#static_list + 1] = r
    local m = static_module[r.internalName]
    if m == nil or r.start < m then static_module[r.internalName] = r.start end
  end
end
```

产物是两张表：

| 表 | 结构 | 用途 |
| --- | --- | --- |
| `static_list` | 数组 `{start, end, state, internalName, …}` | `range_of` 线性反查地址所属段 |
| `static_module` | 哈希 `internalName → 最小 start` | 计算偏移基准、按模块聚拢 |

`static_list` 用数组 + 线性扫描而非区间树：段数量通常在数百级别，线性查找的开销远小于构建索引的成本，且代码更短、更不容易出错。

### 静态判定

```lua
local STATIC_STATES = { Xa = true, Cb = true, Cd = true, Ps = true }
```

两处使用：

1. `load_ranges` —— 构建段表时过滤；
2. `all_static` —— 用 `gg.getValuesRange(sel)` 一次性复核全部勾选项。

`all_static` 对返回形态做了兼容：

```lua
local state = type(info) == "table" and info.state or info
```

不同 GG 版本可能返回 `{state="Cd", …}` 也可能直接返回状态字符串。

> 只要有一项不在白名单内就整体拒绝，不做「部分通过」。因为混入非静态地址会让生成的配置文件在重启后产生**指向随机数据**的写入，风险高于收益。

### 去重

```lua
if it and it.address ~= nil and not seen[it.address] then
```

同一地址可能在保存列表里出现多次（重复保存 / 同一地址不同类型）。去重保留第一条，避免生成脚本重复写同一个位置。

## 记录与校验

### 记录结构

```lua
{
  module     = r.internalName,              -- 完整路径，输出时取 basename
  seg_start  = r.start,
  seg_end    = r["end"],
  offset     = hex_addr(item.address - base),  -- 字符串 "0x…"
  flags      = item.flags,
  value      = value,
  freeze     = freeze,                      -- 已固化的布尔值
  value_addr = hex_addr(item.address),
}
```

三个设计选择：

- **`offset` 存字符串**：直接进入 JSON/CSV/Lua 三处输出，避免各格式化器重复处理；比较时用 `tonumber` 转换。
- **`freeze` 在记录里固化为布尔**：`frozen(freeze, i)` 的「表 / 布尔」双形态只在 `make_record` 调用点解析一次，之后排序、过滤都不会让冻结状态错位。
- **`module` 存完整路径、输出取 `basename`**：完整路径用于去重与排序（不同目录下同名 so 可区分），输出时只保留文件名以便生成脚本直接 `getRangesList(name)`。

### 校验

```lua
local off = row.offset and tonumber(row.offset)
local hit = off and row.seg_start and range_of(row.seg_start + off)
```

等价于 `range_of(原地址)` 再比一次 —— 但用「段基址 + 偏移」重算，验证的是**将要写进文件的那组数值**本身是否自洽，而不是原始输入。若段表在流程中被外部修改（例如模块被卸载），这里就能捕获。

失败项不丢弃，而是先让用户决定是否继续写剩余项；全部失败才终止。

### 排序

```lua
table.sort(rows, function(a, b)
  local sa, sb = a.seg_start or 0, b.seg_start or 0
  if sa ~= sb then return sa < sb end
  if a.module ~= b.module then return a.module < b.module end
  local oa, ob = tonumber(a.offset) or 0, tonumber(b.offset) or 0
  if oa ~= ob then return oa < ob end
  return tostring(a.offset) < tostring(b.offset)
end)
```

三级排序：**段基址 → 模块名 → 偏移（数值）**。目的有两个：

1. 让 `fmt_lua` 的「同模块只输出一次 `so=`」成立（同模块记录必然相邻）；
2. 让同一份输入的输出**逐字节可复现**，便于 diff 与版本管理。

第三级回落到字符串比较，是为了在偏移相等（理论上不会发生，除非重复地址）时保持全序，避免 `table.sort` 的「invalid order function」报错。

## 格式化层

### 格式注册

```lua
local FORMATS = { "lua", "json", "csv" }
local FORMAT_LABEL = { lua = "Lua 脚本 (.lua)", json = "JSON (.json)", csv = "CSV (.csv)" }
local FORMATTERS = { lua = fmt_lua, json = fmt_json, csv = fmt_csv }
```

`FORMATS` 的**数组顺序即输出顺序**，`normalize_formats` / `parse_formats` 都按它重排，保证「无论用户勾选顺序如何，写文件顺序固定」。

新增格式只需三处改动：`FORMATS` 加名字、`FORMAT_LABEL` 加显示名、`FORMATTERS` 加函数。

### Lua 输出

```lua
if r.module ~= cur then
  cur = r.module
  out[#out + 1] = 'so=gg.getRangesList("' .. basename(r.module) .. '")[1].start'
end
out[#out + 1] = "py=" .. hex_addr(tonumber(r.offset))
             .. "\nsetvalue(so+py," .. tostring(r.flags) .. "," .. num_to_literal(parse_num(r.value))
             .. (r.freeze and ",true" or "") .. ")"
```

- 模块切换时才写 `so=`，依靠 `sort_rows` 保证同模块连续。
- `py` 用 `hex_addr(tonumber(r.offset))` 重新格式化 —— 虽然 `offset` 本来就是 `0x` 字符串，这里再过一遍是为了兜住 `tonumber` 失败（理论上不会）。
- `value` 在输出时**再解析一次** `parse_num`：因为用户在阶段 5 可能输入 `0x10` 或 `100~200`，生成的脚本必须拿到纯数值字面量。

> 已知瑕疵：若两个不同路径的模块 `basename` 相同，`so=` 会按完整路径判断「模块变了」，输出两行同名 `so=` —— 功能上不致命（后者覆盖前者），但生成的脚本会取到同一个基址。

### JSON 输出

```lua
s = tostring(s):gsub('[%c"\\]', function(c)
  return JSON_ESC[c] or string.format("\\u%04X", c:byte())
end)
```

`[%c"\\]` 一次匹配控制字符、双引号、反斜杠；`JSON_ESC` 覆盖 `"` `\` `\b` `\f` `\n` `\r` `\t`，其余控制字符走 `\u00XX`。

输出是**手写拼接**而非通用序列化器：字段顺序固定、无尾逗号、每条记录一行，便于肉眼 diff。

`freeze` 用 `r.freeze == true` 严格判定，避免 `nil` / 字符串被写成非布尔值。

### CSV 输出

```lua
if s:find('[,"\n\r]') then return '"' .. s:gsub('"', '""') .. '"' end
```

标准 RFC 4180：仅在必要时加引号，内部引号翻倍。不处理 `\t`（不属于 CSV 特殊字符），也不加 BOM（加 BOM 反而会让部分解析器把表头首字段读成 `\uFEFFmodule`）。

### 路径派生

```lua
local function format_paths(base, fmts)
  local dir, name = dirname(base), basename(base)
  local stem = split_name(name)
  for i = 1, #fmts do out[i] = dir .. stem .. "." .. fmts[i] end
end
```

`stem` 是 `split_name` 的第一个返回值，天然做了「空主干回退为 `out`」的处理，所以 `.lua` 这种纯扩展名输入会得到 `out.lua` 而不是 `.lua`。

## 配置层

### 序列化

```
out_path=<路径>
formats=<lua,json,csv 的子集>
lang=<zh|en>
history_count=<N>
<path1>\x1F<path2>…
```

约束与原因：

| 处理 | 原因 |
| --- | --- |
| `one_line` 把 `\r\n` 换成空格 | 换行会破坏「一行一个 `key=value`」的结构 |
| 历史条目内的 `\x1F` 也换成空格 | 否则解析时会多切出一条假记录 |
| `lang` 必须排在 `history_count` 之前 | 解析端在 `history_count` 处 `break`，之后的字段不会被读到 |
| `lang` 写入前校验 | 只接受 `STR` 里存在的语言键，非法值回落到当前 `LANG` |
| 字段顺序固定 | 便于人工查看与 diff |
| `_loaded` 等内部标记不落盘 | 属于运行时状态 |

### 反序列化

```lua
for line in (text .. "\n"):gmatch("(.-)\n") do lines[#lines + 1] = line end
while #lines > 0 and lines[#lines] == "" do table.remove(lines) end
if #lines < 3 then return nil end
```

容错矩阵：

| 异常 | 行为 |
| --- | --- |
| CRLF / CR | 统一转 LF |
| 尾部空行 | 剔除 |
| 少于 3 行 | 返回 `nil` → 上层回落默认值 |
| 未知 key | 忽略（前向兼容，新增字段不会让老版本判废） |
| `lang` 值不在 `STR` 内（如 `jp` / 空） | 忽略该项，保留默认语言，不判废 |
| `formats` 含非法项 | 丢弃非法项，保留合法项；全非法则保留默认 `{lua}` |
| `history_count` 非数字 / 负数 | 返回 `nil` |
| `history_count` 超上限 | 截断到 `HISTORY_MAX` |
| 历史条目不足 | 有多少收多少 |
| 缺 `history_count` | 返回 `nil`（它同时是「历史段起始」的标记） |

解析在 `history_count` 处 `break`，因为其后的行不再是 `key=value` 结构 —— 继续解析只会把路径当成未知 key 丢掉。

### 双存储

```lua
local ok_file = false
for i = 1, #CFG_FILES do
  if try_write(CFG_FILES[i], plain) then ok_file = true break end
end

local ok_var = false
if gg.saveVariable then
  local ok, res = pcall(gg.saveVariable, { cfg = plain }, Data_Save_file)
  if ok and res ~= false then ok_var = true end
end
```

- 读取：3 个文件候选 → GG 变量槽位，取第一个非空。
- 写入：文件（首个成功即停）+ 变量槽位（**总是尝试**），任一成功即成功。
- `gg.getVariables` 的返回形态在不同版本间差异较大，`cfg_blob_from` 兼容 `{blob}` / `{cfg=blob}` / 裸字符串，`cfg_blob_from_gg` 还兼容「带参 / 不带参」两种签名。

写文件用首个成功就 `break`，是为了避免同一份配置在三个位置各留一份（后续读取时可能读到过期副本）。

### 写入时序

主流程收尾：

```lua
local cfg = read_cfg()
cfg.out_path = written[1]
if remember then cfg.formats = fmts end
write_cfg(cfg)
history_push(written[1])
```

`history_push` 内部**再读一次配置**、只替换 `history`、再写回。也就是说流程结束时实际发生了两次「读 + 写」。这样做的好处是 `history_push` 可独立复用（不依赖调用方传入 cfg），代价是两次磁盘写入。

> 优化点（当前未实现）：把 `history_push` 改成接受 `cfg` 参数，可省掉一轮 I/O。注意 `written[1]` 才是真实路径 —— 写入降级时它可能与用户输入的路径不同，配置里记的必须是它。

## 多语言

### 结构

```lua
local VERSION = "R1"
local LANG    = "zh"
local STR = { zh = { ... }, en = { ... } }
local function t(k, ...) ... end
```

词表是**扁平 key-value**（`app_title` / `menu_flow` / `verify_bad`…），不做嵌套：取词只有一次表查找，缺词回退也简单。带占位符的文案统一走 `string.format`，调用方写成 `t("done", #rows, #written)`。

### `t()` 的三级回落

```
STR[LANG][k]  →  STR.zh[k]  →  tostring(k)
```

| 级别 | 作用 |
| --- | --- |
| 一级 | 当前语言命中 |
| 二级 | 新语言漏译时显示中文，而不是空白 |
| 三级 | key 写错时至少看到 key 名，避免 `nil` 拼进 `gg.alert` 触发 `bad argument` |

参数判断用 `select("#", ...)`：无参就不调 `format`，防止文案里恰好含 `%` 时被当成格式符。

### 语言状态的生命周期

| 时机 | 动作 |
| --- | --- |
| 脚本启动 | `LANG = "zh"`（硬编码默认值） |
| `ensure_cfg()` → `read_cfg()` | 读到合法 `lang` 即覆盖 `LANG`，界面语言对齐用户上次选择 |
| 主菜单「Language / 语言」 | `toggle_lang()`：切换 `LANG` + 写回配置 + toast 确认 |
| 之后每次 `read_cfg()` | 再次以配置值为准（正常情况下与当前值相同，幂等） |

`toggle_lang` 有一个必须注意的顺序问题：

```lua
local next_lang = (LANG == "zh") and "en" or "zh"
local cfg = read_cfg()      -- 这一步会把 LANG 拉回配置里的旧值
LANG = next_lang            -- 所以必须在读配置之后再覆盖
cfg.lang = LANG
write_cfg(cfg)
```

如果先赋值再读配置，刚切好的语言会被读配置还原，表现为「点了没反应」。

### 不翻译的部分

| 内容 | 原因 |
| --- | --- |
| 生成文件的字段名 `module` / `offset` / `flags` / `value_addr` / `value` / `freeze` | 下游脚本按固定字段解析 |
| CSV 表头 | 同上，Excel / pandas 按列名取数 |
| `TYPE_MAP` 的类型名（`Dword[4]` 等） | 是 GG 的 flags 标识，翻译反而误导 |
| 配置文件的 key `out_path` / `formats` / `lang` / `history_count` | 属于存储格式，与界面语言无关 |

### `FORMAT_LABEL` 的角色变化

它曾同时承担「合法性集合」和「显示名」；加入 i18n 后拆成两件事：

```lua
local FORMAT_LABEL = { lua = true, json = true, csv = true }     -- 只做 membership
local function fmt_label(f) return t("fmt_" .. tostring(f)) end  -- 只做显示
```

`normalize_formats` / `parse_formats` 里的 `if FORMAT_LABEL[x]` 判定完全不受影响，界面侧改调 `fmt_label`。

### 命名冲突

`t` 是很短的名字，容易和局部变量撞车。`describe()` 原本有 `local t = item.flags and ...`，加了取词函数后会被静默遮蔽，表现为该函数内 `t(...)` 报「attempt to call a number value」。已改名为 `ty`。`uniq_suffix()` 里的 `local t, r = 0, 0` 因为不调用 `t()`，暂时保留。

### 新增一种语言

1. 复制 `STR.zh` 新建 `STR.ja` 并翻译（缺 key 会自动回落中文，可以先只翻常用项）。
2. `toggle_lang` 改成轮换表：

```lua
local ORDER = { "zh", "en", "ja" }
local i = 1
for k = 1, #ORDER do if ORDER[k] == LANG then i = k break end end
local next_lang = ORDER[i % #ORDER + 1]
```

3. `serialize` / `deserialize` 不用改 —— 它们只做 `STR[lang]` 的存在性判断。

## 界面层的索引映射

GG 的 `gg.choice` / `gg.multiChoice` / `gg.prompt` 都是 **1-based 数组**，而脚本普遍在首位插入「全选」「全部输出」这类元选项，取用时必须做偏移。规则统一为：**元选项占 1 位，业务项从 2 开始，取用时减 1**。

### `step_select_items`

| 界面项 | 下标 | 映射 |
| --- | --- | --- |
| `全选（共 N 项）` | 1 | `chosen[1..N] = true` |
| 第 i 项描述 | i+1 | `chosen[i] = true` |

### `step_pick_freeze`

`gg.choice` 返回 1/2/3，分别对应 `true` / `false` / 逐项表。逐项时用 `collect_chosen` 生成**紧凑**的 `labels` 与对应的原始下标 `keys`：

```lua
local labels, keys, k = {}, {}, 0
for i = 1, #sel do
  if chosen[i] then
    k = k + 1
    labels[k] = describe(sel[i])
    keys[k]  = i          -- 原始下标
  end
end
```

逐项结果表以 `sel` 下标为键、初始全 `false`，所以未勾选项（包括未被选中的项）都是 `false`，语义完整。

### `step_edit_values`

这是最容易看错的一处。构造顺序：

```lua
local defaults, types = { "", false }, { "text", "checkbox" }
-- 先按紧凑下标追加业务项到 defaults[i+2] / types[i+2]
table.insert(labels, 1, "采用单调值")
table.insert(labels, 1, "单调值（勾选后统一改成这个值）")
```

两次「插到第 1 位」使最终顺序反转，得到：

| 最终下标 | 标签 | 控件 | 读取 |
| --- | --- | --- | --- |
| 1 | `单调值（勾选后统一改成这个值）` | text | `res[1]` |
| 2 | `采用单调值` | checkbox | `res[2] == true` |
| 3 … N+2 | 第 i 项描述 | text | `res[i + 2]` |

也就是说**文本框在界面上排第一、复选框第二**，而代码里 `defaults[1]=""`、`defaults[2]=false` 正是按这个最终顺序排的。判断逻辑：

```lua
if res[2] == true then
  local mono = res[1]
  if not has_text(mono) then mono = 0 end
  for i = 1, #keys do values[keys[i]] = mono end
else
  for i = 1, #keys do
    if res[i + 2] ~= nil then values[keys[i]] = res[i + 2] end
  end
end
```

### `step_pick_formats`

| 界面项 | 下标 | 预勾选 |
| --- | --- | --- |
| `全部输出（lua + json + csv）` | 1 | 否 |
| `FORMAT_LABEL[FORMATS[i]]` | i+1 | 若上次记住则 `pre[i+1] = true` |

### `step_output_opts`

`gg.prompt` 两字段：路径（type `file`）、是否记住格式（checkbox）。返回 `res[1]` 路径、`res[2] == true` 记忆标记。

路径默认值做了两道防御：

```lua
if def_path:sub(-4) == ".tmp" or def_path:sub(1, 1) ~= "/" then def_path = DEFAULT_OUT end
```

`.tmp` 结尾说明上次记住了临时文件路径（历史遗留），直接换默认值更安全。

## 入口与主循环

```lua
-- 初始化：先读配置确定界面语言，再检查 session
pcall(math.randomseed, os.time())
ensure_cfg()

if #gg.getRangesList() == 0 then
  gg.alert(t("no_session"))
  return
end

load_ranges()
gg.showUiButton()

while RUNNING do
  if gg.isClickedUiButton() then
    collectgarbage("collect")
    local ok, err = pcall(main_menu)
    if not ok then gg.alert(t("script_err", tostring(err))) end
  end
  gg.sleep(80)
end

if gg.hideUiButton then gg.hideUiButton() end
```

主菜单有三项：

```lua
local choice = gg.choice({
  t("menu_flow"),   -- 1 获取静态基址
  t("menu_lang"),   -- 2 Language / 语言
  t("menu_exit"),   -- 3 退出脚本
}, nil, t("app_title"))
```

四个要点：

1. **初始化顺序**：`ensure_cfg()` 必须在空 session 检查**之前** —— 它内部 `read_cfg()` 会把 `LANG` 设成用户上次选的语言，这样「未检测到内存段」的提示才是正确语言。`load_ranges()` 则必须在检查**之后**，因为空段表时没有必要遍历。
2. **`math.randomseed` 用 `pcall`**：部分环境禁用了 `os.time`（返回 `nil`），`randomseed(nil)` 会抛错。
3. **主循环 80ms 节流**：`gg.sleep(80)` 让出 CPU，避免长时间占用导致 GG 或游戏卡顿；点击时才 `collectgarbage`，把 GC 开销集中在低频路径。
4. **菜单异常不外抛**：`pcall(main_menu)` 失败只弹窗，循环继续 —— 一次误操作不会让整个脚本退出。

`RUNNING` 只由菜单第 3 项置 `false`；其余所有 `nil` 返回都只是 `return`，不改变循环状态。切换语言后菜单在下一次点击时以新语言重绘。

> **注意**：`load_ranges()` 只在入口执行一次。若脚本启动时目标模块尚未加载，段表里就没有它，后续勾选的地址会因 `range_of` 找不到而**静默丢弃**（表现为「没有生成任何静态基址」或记录数变少）。因此**务必先进入游戏、让目标 so 加载完成，再运行脚本**。同理，脚本运行期间新加载的模块不会被感知，需重启脚本。

## 性能与资源

| 操作 | 复杂度 | 说明 |
| --- | --- | --- |
| `load_ranges` | O(段数) | 启动一次，通常数百段 |
| `range_of` | O(段数) | 每地址一次线性扫描；`make_record` + `verify_rows` 共约 2N 次 |
| `all_static` | O(1) 次 API | `getValuesRange` 批量查询，不逐条调用 |
| `sort_rows` | O(N log N) | 比较函数内有 3 次 `tonumber`，N 通常 < 100 |
| 写入 | O(格式数 × 重试数) | 每格式独立重试，最坏 3 目录 × 若干回退分支 |

内存占用主要来自 `static_list`（段对象引用，不复制）与输出文本（N 条记录拼成的字符串，量级为 KB）。无缓存、无全局累积，脚本结束即释放。

## 可扩展点

### 新增输出格式

1. `FORMATS` 数组追加名字（决定输出顺序）。
2. `FORMAT_LABEL` 加显示名（自动出现在格式选择框）。
3. 写 `fmt_xxx(rows)`，入参是已排序的记录数组，返回完整文本。
4. `FORMATTERS` 注册。

无需改动界面层 —— `step_pick_formats` 全部按 `FORMATS` 迭代。

### 扩展静态段白名单

```lua
local STATIC_STATES = { Xa = true, Cb = true, Cd = true, Ps = true }
```

按 ROM 实测结果追加状态码即可，两处使用点（`load_ranges` / `all_static`）自动生效。建议先用 GG 的「内存段列表」观察目标地址的实际 state，再决定是否加入。

### 放开历史条数

```lua
local HISTORY_MAX = 1
```

改成 `10` 即可：`deserialize` 已支持多值解析，`serialize` 也会按 `#h` 写出。但 `history_push` 目前是 `cfg.history = { path }`（直接覆盖），要真正保留多条需改成 `table.insert` + 截断：

```lua
local cfg = read_cfg()
table.insert(cfg.history, 1, path)
while #cfg.history > HISTORY_MAX do table.remove(cfg.history) end
write_cfg(cfg)
```

### 新增界面语言

见 [多语言 · 新增一种语言](#新增一种语言)。核心是加一张 `STR.xx` 表并扩展 `toggle_lang` 的轮换顺序，配置层与界面层都不用改。

### 更换默认输出位置

`DEFAULT_OUT` 由 `SCRIPT_DIR` 派生。若想默认写到 `Download` 目录：

```lua
local DEFAULT_OUT = "/storage/emulated/0/Download/已输出的基址.lua"
```

注意 `SCRIPT_DIR` 的推导依赖 `gg.getFile()`，在部分 GG 版本中返回 `file://` 或空串，脚本已做 `file://` / `document://` 剥离与「不以 `/` 开头则回落 `/storage/emulated/0/`」的处理。

### 生成脚本改为「遍历所有匹配段」

当前生成的是 `getRangesList(name)[1].start`。若要更稳，可改为按最小 start 取：

```lua
local rs = gg.getRangesList("libxxx.so")
local base = math.huge
for i = 1, #rs do if rs[i].start < base then base = rs[i].start end end
so = base
```

这与本体的 `static_module` 计算口径完全一致，可消除「多份映射取错」的风险。

## 调试建议

1. **先验证段表**：在 GG 控制台手动执行 `gg.getRangesList()` 并观察目标地址的 `state`，确认它在 `STATIC_STATES` 内。
2. **打印中间记录**：在 `make_record` 之后临时加 `print(module, offset, flags, value)`，确认偏移基准是「最小 start」而不是「首个匹配」。
3. **核对输出路径**：写入降级时以弹窗回执为准；`cfg.out_path` 记录的是 `written[1]`。
4. **单独测试生成的脚本**：把生成的 `.lua` 放到 GG 里直接运行，观察是否报 `index a nil value`（模块未加载）。
5. **复现写入失败**：在目标目录先 `touch` 一个同名只读文件，可稳定触发 `try_write` 的回退分支，用于验证降级逻辑。
6. **不要在生产环境试 `STATIC_STATES`**：加入非静态段状态会让偏移在重启后指向随机数据，可能写入游戏的其他结构，风险不可控。
7. **验证语言切换**：手动把配置文件改成 `lang=en` 后重启脚本，若界面仍是中文，说明 `read_cfg` 没读到该文件（可能被 `/sdcard/Lib_Tool.R1.cfg` 的旧副本抢先），删掉多余副本即可。
8. **Lua 版本兼容**：`for` 的控制变量在 Lua 5.4+ 是只读的（`attempt to assign to const variable`）。当前版本已把 `parse_formats` 里对循环变量的重新赋值改为新建局部变量，改脚本时注意不要写出 `for k in ... do k = f(k) end` 这种形式。
